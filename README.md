# CRM мероприятий

Русскоязычное приложение для команды мероприятия. Для его работы нужны Node.js 24, npm, Supabase CLI 3 и Docker.

## Локальный запуск

1. Выполните `supabase start`. В локальной конфигурации уже отключены публичная регистрация и анонимные сессии. При запуске создаётся приватный bucket `crm-task-files`.
2. Скопируйте `.env.example` в `.env.local` и укажите адрес API и ключ Publishable. Приложение проверяет формат ключа перед сборкой.
3. Выполните `npm ci`, затем `npm run dev -- --host 127.0.0.1`. Для проверки промышленной сборки используйте `npm run build`.
4. Для первого мероприятия администратор создаёт аккаунт через Auth в Supabase Studio, затем создаёт профиль, мероприятие и запись `event_members` с ролью `coordinator` в одной транзакции. Остальных добавляет координатор через «Команда» → «Пригласить участника». Edge Function `invite-member` создаёт профиль и членство по электронной почте. Письма локального Auth доступны в Mailpit.

Если стек был запущен без Edge Runtime, выполните `supabase functions serve` в отдельном терминале, чтобы включить приглашения.

## Управление разделами

Координатор может создавать и переименовывать направления, переименовывать стандартные вкладки и создавать вкладки с текстовыми страницами. В меню мероприятия откройте «Управление разделами». Архив вкладок убирает их из меню. Для встроенных экранов сохраняются ссылки из задач и других карточек. Архив направления убирает его из рабочего списка, сохраняя связанные задачи и историю. Новые задачи создаются в активных направлениях. Координатор может восстановить раздел из архива.

Координатор может назначать ответственных прямо в карточке направления или через «Команда» → «Руководство направлениями». Оба экрана показывают подтверждённые назначения.

## Карточки направлений

В направлении показан список с названием, статусом и суммой. Полная карточка открывается по названию. Координатор и руководитель направления могут добавлять и редактировать исполнителей, заведения и других контрагентов, указывать стоимость или сумму, комментарий и несколько контрольных дат с названиями.

В списке спонсоров показывается полученная сумма, а до её заполнения — обещанная. В полной карточке доступны обе суммы, компания, контакт и назначение ответственного. Ответственный может обновлять контактное лицо, оба статуса, суммы и контрольные даты своей карточки. При заполнении полученной суммы выберите отметку «Получили деньги».

## Билеты

В разделе «Столы и бронирование» изначально доступны столы № 1–20 по 12 мест. Координатор и руководитель «Билетов» могут добавить стол со следующим номером и такой же вместимостью. По каждому столу видны свободные, забронированные и проданные места. При бронировании записывают имя, количество мест и дату. Если дата прошла, резерв сохраняется до выкупа или ручного снятия.

Выкуп всей брони меняет статус мест на «Продано» и создаёт одну запись об оплате. При продаже без брони нужно выбрать стол. Более ранние продажи без номера стола остаются в журнале и входят в общую выручку.

В направлении «Билеты» координатор и руководитель записывают и исправляют продажи. Можно менять стол, количество билетов, общую сумму и способ оплаты. При правке продажи по выкупленной брони стол и число мест меняются и в брони. Журнал пересчитывает количество проданных билетов, наличные, безналичные и общую выручку.

Координатор может удалить продажу из рабочего журнала. Она сохраняется в истории «Удалённые продажи» и исключается из выручки. Места по прямой продаже освобождаются, а при выкупе возвращаются в бронь с прежним сроком.

В блок «Расстановка столов» можно загрузить готовый PDF, PNG, JPEG или WebP размером до 20 МБ. Предыдущие версии доступны для просмотра. Итоги продаж и схемы видны активным участникам мероприятия.

Локальный `supabase start` создаёт приватное хранилище `crm-ticket-layouts`. Для будущей публикации создайте это хранилище в выбранном проекте с параметрами из `supabase/config.jsonc`.

## Финансы

Вкладка «Финансы» доступна координатору. Она показывает фактически полученные спонсорские взносы и продажи билетов. Фактический остаток равен поступлениям за вычетом оплат. Остаток после оплаты резервов дополнительно учитывает все неоплаченные обязательства.

Сумму задачи в рублях могут указать координатор, руководитель направления, ответственный и соисполнители. По умолчанию используется тип «Расход». Для ожидаемой оплаты выбирают «Поступление». В финансовом плане сумма родительской задачи включает её подзадачи. При пустой сумме родителя учитываются суммы подзадач. Отменённые задачи в план не входят.

Карточка контрагента с положительной суммой и статусом «Согласились» автоматически появляется в резервах. Координатор записывает оплату всей суммы, указывая дату и способ. После этого сумма сохраняется в журнале оплат, а повторный резерв по карточке не появляется.

## Проверка прав

`supabase/tests/rls.sql` проверяет SQL-привилегии, RLS, согласованность связей, дерево задач, журнал и изоляцию вложений. Запускайте файл целиком в отдельной сессии локальной базы после миграций. Записи теста откатываются в этой же сессии.

## Публикация

Рабочий процесс Pages запускается вручную. Перед публикацией укажите HTTPS-адрес API и ключ Publishable выбранного проекта в переменных среды GitHub `github-pages`. В Supabase примените миграции, разверните функцию `invite-member` и создайте приватные хранилища `crm-task-files` и `crm-ticket-layouts` с параметрами из `supabase/config.jsonc`. В Supabase Auth укажите корневой адрес сайта в Site URL и в списке разрешённых адресов возврата. Проверьте доставку писем на адреса участников.
